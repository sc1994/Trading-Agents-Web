# A 股持仓与收盘风险检查：第一期设计

## 状态与目标

本文是待用户审阅的设计，不代表功能已经实现。用户已确认：手动录入持仓；每日收盘后检查；支持短线、中线、长期计划；第一期优先 A 股，非 A 股明确提示当前不支持。

第一期把现有单股研究工作台扩展为可持续使用的个人持仓清单。用户可以维护持仓、自选股与观察条件，在收盘检查后查看触发依据，并进入已有分析流程。机会自动筛选、券商同步、自动交易、盘中行情和外部消息推送不在本期范围。

## 现有能力与实现选择

- `web/store.py` 使用私有目录中的 SQLite 保存 tasks、events、sections、settings，没有真实持仓数据。
- `web/api.py` 的 TaskInput 不接收成本、股数、投资周期和用户观察条件。
- `web/reports.py` 仅投影已有报告字段；报告里的 time_horizon 是模型输出，不是用户设定的计划。
- `web/runner.py` 与 `web/worker.py` 串行运行分析。行情检查不能占用这一 LLM 队列，也不能修改其进程级凭据环境。
- `web/search.py` 已支持股票搜索；`.[search]` 额外依赖与 Web 镜像包含 AKShare，但当前没有收盘检查服务。

采用独立的 Web 层投资数据与检查服务，复用 SQLite、股票搜索、任务创建和报告页面。拒绝把持仓塞进 tasks.params：任务是一次研究的不可变记录，持仓是独立维护的数据，两者生命周期不同。也不在第一期接入外部券商账户或同花顺私有接口。

## 市场与身份边界

- 只允许人民币计价的沪、深、北交易所 A 股普通股票；不支持港美股、加密资产、ETF、债券、B 股等。沪深股票使用现有 `.SS` / `.SZ` 标识，北交所使用独立明确的 `.BJ` 标识。
- 在新增清单功能中校验交易所、代码与证券类型，不能只凭 STOCK/EQUITY 标签判定 A 股。通过股票名录核实身份；名录不可用或证券未确认时拒绝保存并说明无法确认，不能把猜测的市场身份作为已支持。
- 手动输入代码也必须经过相同核实；裸代码不能不经核实就按前缀假定交易所。维护 A 股名录时保留交易所信息，北交所通过其名录来源补齐。
- 搜索结果中的非 A 股显示禁用状态与“当前持仓与收盘检查仅支持 A 股”，后端也返回结构化错误。该限制不影响原有单股分析的市场范围。
- 仍是单用户、私有研究工作台，不新增账户系统。真实金融记录依赖现有反向代理访问控制，不新增公开访问入口。不得将真实持仓写进日志、测试、截图或 Git。

## 数据结构

沿用现有数据库与私有文件权限，使用增量建表迁移，不改写旧任务、设置或报告。

| 新增记录 | 主要内容 |
| --- | --- |
| instruments | 规范代码、名称、交易所、币种、证券类型、身份核实时间；同一代码唯一 |
| watchlist | 股票引用、关注理由、创建与更新时间；同一股票只保存一条关注记录 |
| holding_plans | 股票引用、short/medium/long、持有股数、每股成本、买入理由、可选观察条件、成本待核对标记、revision、active/closed、创建与更新时间 |
| close_checks | 请求与目标交易日、queued/running/completed/partial/failed/interrupted、开始与完成时间、自动或手动来源 |
| check_results | 检查引用、计划 ID 与 revision、当时的计划快照、报价日期与来源、收盘价、计算结果、触发条件、缺失或异常原因 |
| holding_settings | 自动检查开关、可选单股集中度上限；不与现有供应商 PATCH 混用 |

持仓计划是当前持有数量的手动快照，不是券商成交账本。用户买入、卖出后手动更新股数与成本，关闭计划表示当前不再持有；历史检查仍保存当时快照。允许同一股票有多个不同周期计划；它们相互独立，共用一个股票报价。

股数采用正整数，上限为 10 亿股；允许非整手持仓，但不允许负数和零股的活动计划。成本与价格通过 Decimal 校验和计算，以十进制字符串持久化与传输，最多 12 位整数和 6 位小数，拒绝科学计数法、NaN、无穷和非正值。费用、分红、税费不自动计入：展示的是按用户录入成本计算的未实现盈亏，不是账户总收益。持仓修改使用 revision 校验，过期编辑返回冲突。

每个计划只需代码、股数、成本、投资周期；理由和条件可后补。支持的条件为：收盘价不高于下观察线、不低于上观察线，以及到达用户指定复核日期。上下线必须为正值，同时设置时下线小于上线；没有默认止损比例。集中度阈值默认未设置，不替用户决定风险偏好。

## 收盘数据与质量控制

新增独立行情适配器：首版使用 AKShare 的 A 股日线历史数据与交易日历入口，取不复权日线收盘价，固定可信上游，不接收用户指定 URL。保留 provider、price_date、fetched_at、currency 与数据质量状态；本期数据属于非交易级公开数据，不承诺可用性或实时性。

交易日历用来确定 Asia/Shanghai 下最近已收盘交易日。日历必须覆盖目标日期；周末可以判定休市，但不能把缺失日历中的工作日直接判成休市。若来源无法确认节假日或当前交易日，返回“交易日历不可用”，不产生正常检查结论。交易日历与名录分别缓存并记录有效范围，测试使用固定注入数据。

报价必须具有目标交易日对应的完整日线、正有限收盘价及正确证券身份。目标日无报价、停牌、报价过期、错误币种或来源错误均标记为无法检查；保留旧报价供参考，但不据此生成今天的“未触发”结论。正常与缺失结果共同存在时，本次检查为 partial。

不复权价格与手动成本保持同一价格口径。第一期不自动识别公司行动，也不自动修正股数或成本，界面明确提醒送转等事件后需手动维护。用户可以标记“成本待核对”，此时暂停该计划价格条件和盈亏计算，直至重新确认股数、成本与观察线；日期复核仍有效。不能声称自动覆盖全部公司行动风险。

外部请求必须有可验证的总时限和有限重试。若 AKShare 调用本身不能可靠限制请求时间，将抓取封装在可终止的独立进程中，超时终止并记录失败，不能仅依赖无法终止线程的 future 超时。上游异常不返回原始堆栈或请求内容。

## 检查调度与规则

应用新增独立的单进程检查工作器，在 lifespan 中启动并关闭；不引入 Redis、Celery 或新服务。报价与日历调用不占用数据库事务，也不持有分析运行锁。

- 自动检查默认启用；在每个已确认的 A 股交易日 16:30（Asia/Shanghai）后发起一次。当天收盘后启动应用可补跑；不回填应用离线期间的历史持仓检查，因为没有历史持仓账本。
- 自动检查使用目标日期与尝试序号唯一标记，避免线程轮询或重启重复创建。暂时缺失数据可在当日有限重试，包括首次在内最多三次，间隔至少 30 分钟；结束后等待手动重试或下一交易日。手动检查成功后，自动调度不再为同一目标日期重跑；计划修改后由用户手动重查。
- 页面有“检查最新收盘数据”。后端确定日期，客户端不能传任意历史日期；16:30 前指向最近已完成的交易日。
- 同一时间只运行一项检查；重复手动点击返回已存在的进行中检查。单次检查最多覆盖 100 个唯一股票，清单新增超过限制时明确拒绝。相同股票只抓取一次数据。
- 入队后、实际开始时读取全部活动计划形成输入快照，结果关联 plan_id 与 revision。检查过程中修改计划不污染该次结果；页面标注“计划已修改，结果待更新”。
- 重启把遗留 running 检查标为 interrupted；手动重试建立新检查，不把未完成结果当作成功。关闭时禁止新的请求并有界清理行情进程。

规则只计算用户明确设置的条件：下线使用 `close <= lower`，上线使用 `close >= upper`，日期条件使用 `target_date >= review_date`。到期条件不依赖报价，但不能掩盖同时存在的价格检查失败。状态为待复核、已设条件未触发、未设置条件或无法检查；“未触发”不代表投资安全，也不代表基本面没有变化。

汇总市值与浮动盈亏按同一目标交易日计算，标明“按本次录入持仓与该日收盘价估算”，不把当前持仓当作历史成交记录。同一股票的不同计划先汇总，再计算单股集中度。集中度分母只包含录入的活动股票市值，不含现金或未录入资产；名称明确为“已录入股票持仓占比”，不能称为账户总仓位。任一活动持仓缺失有效报价、计划已修改或成本待核对时，汇总显示不完整，不生成集中度提醒。

## API 与前端

新增独立的 `/api/portfolio` 路由与严格请求模型：

- instruments/search：复用搜索并返回清单支持状态；身份确认使用 A 股名录服务。
- watchlist：查询、新增、修改关注理由与删除；删除自选不删除持仓或研究报告。
- plans：查询、新增、带 revision 更新；close 是显式关闭命令，不硬删除历史记录。
- settings：查询与更新检查开关及可选集中度阈值。
- checks：创建最新收盘检查并返回 202；查询最新与指定检查，包括逐计划结果和数据质量。
- overview：返回活动计划、最近检查状态及有口径说明的汇总，不在 GET 请求中调用外部行情。

业务校验错误包含固定 code 与字段名，支持非 A 股、身份无法确认、版本冲突、行情不可用等中文提示。接口不能将完整任务图状态或供应商密钥带入新响应。

增加 `/holdings` 和 `/watchlist` 页面及导航，保留原有 `/` 分析页面和所有任务、报告、设置链接。持仓页优先显示待复核项、检查日期和不完整数据，其次按股票分组展示计划。表单使用周期分段控件、数字输入、可选观察条件；每条计划显示股数、成本、理由和上次检查状态。小屏改为可扫描的纵向布局，不出现横向溢出。

自选股页支持单条添加、关注理由修改、删除和“建立持仓计划”；本期不做自动机会排序或批量文件导入。两页均提供“发起研究”，进入现有分析表单，预填代码、名称和最新已收盘日期；仍由用户确认模型与参数后提交。

关联报告使用规范股票代码展示该股票已完成的研究记录，清楚显示分析日期与报告时间。不按最新完成时间把旧日期重跑的报告标成最新市场观点；修改持仓不修改报告。报告入口标注“通用单股研究，未结合你的持仓条件”，不把周期或成本塞进现有 TaskInput，也不暗示已经实现个性化 AI 风控。删除报告不会删除计划。

遵循现有 Ant Design 与图标约定，保留加载、空清单、保存错误、检查中、部分失败和重试状态。概念稿里“长期核心逻辑未变化”的表述不进入本期实装，因为第一期没有这种事实核验能力。

## 验证与交付

数据库测试覆盖旧库迁移、持仓独立于任务、同股多计划、Decimal、更新冲突、关闭计划和历史快照保留。API 测试覆盖市场身份、非 A 股提示、非法数值与请求、清单上限、幂等进行中检查、旧任务接口兼容。

行情与调度测试使用注入的时钟、日历和报价，覆盖沪深北股票、盘前/盘后、周末节假日、日历不完整、重启补跑、有限重试、超时、过期数据、停牌和手动成本待核对状态。规则测试覆盖等于阈值、无条件、日期条件、同股汇总、缺失报价及费用口径；不得用真实行情稳定性替代单元测试。

前端测试覆盖新增/编辑/关闭计划、自选转持仓、非 A 股禁用、检查状态、缺失数据、计划修改后旧结果标识、研究表单预填及报告口径。运行相关 Python 测试、TypeScript 测试与构建；用无头浏览器验证桌面和手机，并交付使用虚构数据的截图，不要求用户访问本地 URL。

编码交付前提交 PR，不合并或部署生产。PR 说明新增字段、数据来源限制、收盘检查口径与验证结果。本设计经用户审阅确认后，再编写实施计划并进入编码。
