# Trading Agent Web 个人研究工作台设计规格

日期：2026-09-23
状态：待用户审阅书面规格

## 目标与依据

将现有 TradingAgents 的空白 Web 入口建设为可在电脑和手机使用的单用户研究工作台。用户可以搜索标的、发起一次分析、阅读逐阶段产出与最终五级评级、回看或重跑历史任务，并在受信任的私有环境中配置 API Key。首版不下单，也不提供账户、持仓和团队功能。

产品决策详见 `docs/design/trading-agent-web-product-definition.md`；已确认的首页、搜索、运行、报告、历史和设置桌面/手机草图存放于 `docs/design/assets/trading-agent-web-*.png`。草图是视觉和信息层级参考，不代表虚构示例内容都可从引擎取得。

## 实现路线与边界

采用单个可部署服务：FastAPI 暴露 JSON API、SSE 与编译好的 React/TypeScript/Vite 静态资源；前端统一使用 Ant Design。服务端以 SQLite 持久化 Web 配置、任务、事件和报告，后台执行器串行调用现有 `TradingAgentsGraph`。现有 LangGraph SQLite 检查点与 Markdown 报告仍保留，Web 数据库存储供查询的报告副本；二者用途不同，不把 Web 数据库当作图检查点。

当前 `web/server.py` 和 `web/Dockerfile` 仅服务空白 HTML 与健康检查；实施时需替换/扩展 Web 应用和镜像，使镜像内同时具备前端构建产物及 Python TradingAgents 依赖。运行数据、API Key、报告、记忆和检查点必须挂载持久目录，不能依赖当前只读镜像文件系统。保留 `/healthz` 语义，并调整已有网关测试，不改变私有网络访问边界。首版假设一个应用进程管理一个任务执行器；多进程/多副本扩容不在范围内，启动配置应禁止多 worker 竞争。

## 页面与交互

1. **发起分析（首页）**：输入股票代码或英文名称选择资产，确认分析日期、深度、语言、自动识别或手动修改资产类型；高级项折叠显示供应商、快/深模型、分析师和辩论轮次。缺少必要密钥、无效日期或无效代码时给出字段级反馈；有效提交后进入新任务页。标准分析只提交已选择的配置，不隐含真实交易。
2. **任务运行**：展示排队、运行、失败、中断和完成状态；运行时以分析师、多空研究、交易员、风险团队、组合经理五组阶段组织节点进度。每次已产出的报告可立即阅读；动态列表只展示已完成的节点/阶段和可确认的当前工作节点，不暴露模型内部思维链。浏览器断开不影响执行，刷新后从服务端快照恢复状态。
3. **决策报告**：第一屏展示原生五级评级及原报告中的执行摘要、投资论证、价格目标（有值时）和风险依据；以下使用可切换分区呈现分析师报告、研究辩论、交易计划、风险讨论与组合经理决策。提供 Markdown 导出及复制原参数再次分析。若评级不可解析则标记“需复核”，绝不将其改写为持有；无可验证字段时标记“未提供”。“信号强度”“置信度”并非现有组合经理数据，草图里的这些数字/词仅为示例，首版不展示，也不新调用 LLM 生成依据或风险。
4. **任务历史**：按标的代码/英文名称搜索、状态和评级筛选；展示排队、运行、已完成、失败、已中断记录。可打开进度或报告、恢复可恢复的任务、复制参数创建新任务、单条删除历史任务。删除需确认，并且只删除该 Web 任务及其专属报告，不能删除共享决策记忆、其他任务数据或全局检查点。
5. **设置**：密码框录入/替换/清除模型与数据源密钥；显示是否已配置及最多末尾四位。可选择默认供应商、快/深模型、默认语言与检查点恢复。连接测试由用户显式触发，错误信息脱敏；未配置的可选供应商不会阻挡其他供应商运行。

手机与桌面功能等价。桌面使用侧边导航、多栏进度和报告区域，手机使用单列内容、底部导航、可横向滚动的阶段/报告分区与足够的固定导航避让空间。维持草图的浅色中性背景、绿色主色和 8px 控件圆角，风险和错误另用语义色；不做营销首屏、深色主题、PWA 或通知。

## 标的检索

前端对至少两个字符的输入做约 300ms 防抖，通过 Web 后端请求 `yfinance.Search`。服务端限定查询长度、返回条数及超时，结果只包含代码、名称、交易所、资产类别，并缓存 10 分钟；列表按原服务相关度展示，代码精确匹配优先。选择建议项后将其标准代码作为任务输入。无结果、超时或 Yahoo 限流时允许手动输入符合现有代码校验规则的标的；英文名称不能直接作为代码提交。对于仅一个字符的合法代码可直接手输；中文名称搜索不作首版承诺。外部返回文本按普通文本渲染，不作为 HTML 注入。

## 数据与任务生命周期

Web 数据库记录任务 ID、标的代码与显示名称、日期、完整配置快照（不含 API Key）、时间戳、状态、当前节点/阶段、评级及错误摘要；任务事件记录递增序号、时间、事件类型和可展示的报告增量；报告正文按任务与章节持久化。配置表保存默认设置与密钥状态。任务的 API Key 从服务端配置读取，绝不写入任务快照、SSE 事件、异常正文或前端本地存储。

单执行器按创建顺序领取待处理任务。任务状态为 `queued -> running -> completed | failed | interrupted`；新建任务也可因输入错误被 API 拒绝而不入队。执行器使用现有图流逐节点更新进度和报告，最终在落库完成状态前保存完整报告与最终决策。只有持久化成功后才广播完成事件，避免界面出现完成但报告不可读。任务失败保留已产生的章节并显示脱敏错误摘要，不生成最终评级。页面只显示真实节点状态，不推算无法证明的精确百分比或剩余时间。

服务重启后，先将遗留 `running` 状态标记为 `interrupted`，再领取队列；保留原进度与报告。检查点默认启用，用户可对有兼容检查点的中断任务显式继续；恢复复用原标的、日期、分析师及图形状配置，使用图自带的 `begin_checkpoint`/`checkpoint_input`/`end_checkpoint` 生命周期。无检查点或配置已不可用则只允许复制参数创建新任务。由于现有检查点线程以标的、日期、图形状确定，而非任务 ID，重跑同一标的/日期前必须处理残留检查点，防止不相关任务继承旧状态；任务删除不可误清理其他任务在使用的检查点。首版不提供运行中取消。

SSE 连接时先取数据库任务快照，再按事件序号订阅增量；断线利用 `Last-Event-ID` 或相同游标补取，心跳保持连接。事件只含公开可展示内容；客户端按序去重，报告以持久化版本为准。前端在 SSE 不可达时仍可刷新快照查看结果。后台运行独立于浏览器请求生命周期。

## API 草案

- `GET /api/assets/search?q=...`：受限、可缓存的标的搜索。
- `POST /api/tasks`：验证参数并排队，返回任务 ID；不得包含或返回 API Key。
- `GET /api/tasks`、`GET /api/tasks/{id}`：筛选历史与任务快照。
- `GET /api/tasks/{id}/events`：可按事件序号恢复的 SSE。
- `GET /api/tasks/{id}/report`、`GET /api/tasks/{id}/report.md`：结构化章节和 Markdown 导出。
- `POST /api/tasks/{id}/resume`：只允许可恢复中断任务。
- `POST /api/tasks/{id}/rerun`：复制参数建立新任务；旧任务保持不变。
- `DELETE /api/tasks/{id}`：确认后单条删除；运行中的任务拒绝删除。
- `GET /api/settings`、`PATCH /api/settings`：返回脱敏状态，更新允许项。
- `POST /api/settings/test-connection`：按当前服务器配置测试所选供应商，返回脱敏结果。
- `GET /healthz`：保留健康检查。

API 均按私有网络单用户使用设计，不提供浏览器可读密钥。修改设置/创建删除任务等写操作须防止跨站请求伪造（同源限制及拒绝跨源请求），不允许配置任意内网 URL 供匿名探测。若未来暴露公网，需先单独设计身份验证、传输加密和密钥保护，不得把当前安全假设直接搬到公网。

## 验收与测试

- 单元测试覆盖代码搜索映射、超时/限流和手输降级、输入校验、五级评级及 `REVIEW` 映射、报告缺项、密钥脱敏、任务状态转换和事件游标。
- 使用替身图执行器完成 API 集成测试：排队串行、逐节点事件、断线重连补发、失败保存部分报告、服务重启标记中断、检查点存在/缺失两种恢复、重跑不覆盖旧任务和单条删除边界。不在 CI 调用付费模型或真实行情 API。
- 更新现有 `/`、`/healthz`、HEAD 与未知路由网关测试，测试单镜像静态资源和 API 共存；运行镜像需验证持久化目录与非 root 权限。
- 前端对表单、搜索下拉、进度、结果、历史和设置覆盖加载/空/失败状态；桌面 1440x1000 和手机 390x844 截图检查文字、菜单、按钮和底部导航无重叠。截图为验收产物，不要求用户打开本地开发地址。

## 非目标与已知限制

首版不包含真实交易、实时行情看板、自动调度、多用户、账号权限、主动取消、深色模式、原生 App、PWA 通知、跨实例并发执行或密钥加密服务。密钥保存在服务器本地受限文件/数据库中，密码输入框只遮挡屏幕，不等于加密存储。公开 Yahoo 搜索无服务级保证，因此始终保留合法代码手输。完整任务历史默认长期保留，只有用户逐条删除；磁盘容量由部署维护者监控。
