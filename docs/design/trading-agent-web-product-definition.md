# Trading Agent Web 产品定义与决策记录

更新日期：2026-09-23

状态：首版产品边界已确认；具体实现以对应正式设计规格为准。草图中的示例数据不构成计算能力承诺。

## 1. 产品定位

Trading Agent Web 是面向个人用户的 Trading Agent 研究与决策工作台。

它的首要价值不是替代券商交易终端，而是让用户能够快速发起一次多 Agent 分析，清楚看到分析进度，理解最终结论及其依据，并方便地回看历史研究结果。

首版核心流程：

1. 输入交易标的并选择基础分析参数。
2. 启动 Trading Agent 分析任务。
3. 查看任务阶段和当前已生成的内容。
4. 阅读最终决策摘要、关键依据与主要风险。
5. 下钻查看各分析阶段的完整报告。
6. 从历史记录中重新打开或再次运行既有任务。

## 2. 已确认的目标用户与使用环境

- 目标用户：个人研究者，首版按单用户设计。
- 访问环境：仅本人可访问的内网或私有网络。
- 首版不建设多用户账号、团队空间、角色权限、评论或审批系统。
- 首版不接入券商账户，不执行真实订单。
- 首版不以行情盯盘或持仓管理作为主功能。

## 3. 已确认的信息架构

### 3.1 发起分析

这是默认首页，也是产品的主入口。

基础配置直接展示：

- 交易标的。
- 分析日期。
- 分析深度。
- 报告语言。
- 资产类型可以自动识别，并允许用户修正。

高级设置默认折叠：

- LLM 供应商。
- 快速推理模型与深度推理模型。
- 参与分析的 Agent。
- 研究辩论轮次。
- 风险讨论轮次。
- 其他现有 TradingAgents 配置中适合按任务覆盖的参数。

默认路径必须足够短。用户使用系统默认值时，只需填写或确认基础配置即可启动任务。

交易标的使用可检索下拉选择器：

- 用户可以输入股票代码或英文公司名称，例如 `NVDA`、`NVIDIA`、`0700.HK` 或 `BTC-USD`。
- 输入至少 2 个字符后延迟约 300ms 发起搜索，避免每次按键都请求外部服务。
- 下拉结果展示标准代码、公司或资产名称、交易所和资产类型。
- 用户选中结果后，任务实际提交标准代码，而不是显示名称。
- 首版通过后端调用现有 `yfinance.Search`，无需新增 API Key。
- 搜索结果缓存 5-10 分钟，并限制返回数量，降低 Yahoo Finance 限流风险。
- 搜索超时、限流或无结果时，仍允许用户直接输入合法代码并继续分析。
- 已验证股票代码和英文名称可以正常搜索；Yahoo Finance 对中文公司名称搜索不可靠，首版不承诺中文名称检索。

### 3.2 任务运行

运行页的信息重心是“阶段进度 + 当前产出”，而不是展示完整的模型思维过程。

主要阶段：

- 分析师团队。
- 多空研究团队。
- 交易员。
- 风险管理团队。
- 组合经理。

页面应展示：

- 当前阶段、已完成阶段与后续阶段。
- 当前正在工作的 Agent。
- 已完成阶段生成的报告内容。
- 任务开始时间、持续时间和运行状态。
- 明确的失败信息与可恢复操作。

Agent 原始对话和辩论记录属于可展开的辅助信息，不占据默认主视图。

关闭浏览器不应终止正在执行的任务。重新进入页面后，应能够继续查看任务状态。

### 3.3 分析结果

结果页第一屏优先展示决策摘要，而不是直接展示长篇完整报告。

决策摘要至少包括：

- 最终评级或交易信号。
- 核心理由。
- 主要风险。
- 关键价格或市场依据。
- 分析标的、日期、深度与完成时间。

原始引擎提供五级评级（Buy、Overweight、Hold、Underweight、Sell），解析失败时显示“需复核”，不能默认为“持有”。草图中的“信号强度”不是现有引擎的独立输出字段，首版不计算或展示该指标；关键依据和风险须有可追溯的原始报告内容，缺失时标记“未提供”，不能编造。

完整报告作为下钻内容，按现有 TradingAgents 工作流组织：

- 市场与技术分析。
- 情绪分析。
- 新闻与宏观分析。
- 基本面分析。
- 多空研究辩论及研究经理结论。
- 交易计划。
- 风险团队讨论。
- 组合经理最终决策。

### 3.4 任务历史

系统需要保存完整任务历史，包括：

- 任务输入参数。
- 排队、运行、完成、失败或中断状态。
- 阶段进度与时间信息。
- 最终决策摘要。
- 完整报告。

用户应能够浏览、搜索和重新打开历史任务。基于既有任务再次运行时，应复制原参数后创建新任务，不覆盖旧记录。
历史记录默认长期保留，并提供单条删除；删除不应影响全局决策记忆或其他任务的检查点。

### 3.5 设置

首版提供轻量设置页，用于录入 LLM 与数据源 API Key 及选择默认供应商和模型。

- API Key 使用密码输入框。
- 保存后页面不返回完整值，只显示“已配置”和脱敏后的少量末尾字符。
- 不引入复杂的密钥管理或独立加密系统。
- 配置保存在服务端本地，不保存在浏览器本地存储中。
- 该简化方案以单用户私有网络部署为前提。

## 4. 桌面端与手机端

产品使用同一套响应式 Web，不单独开发原生 App。

- 桌面端使用侧边导航和多栏布局，提高扫描与对比效率。
- 手机端使用单列布局和底部导航，保证触控目标尺寸和文本可读性。
- 手机端与桌面端共用任务、报告、历史和设置 API。
- 可以在后续加入 PWA 安装能力和任务完成通知。

首版手机端与桌面端功能相同，包括完整高级设置、运行进度、长报告、历史记录与密钥设置。仅布局和导航方式不同。

## 5. 前端设计约束

- 技术栈：React、TypeScript、Vite。
- UI 组件体系：Ant Design。
- 产品形态是工作台，不制作营销式首页。
- 视觉语言：冷静、可信、清晰，强调信息层级与证据，不使用装饰性科技感效果。
- 默认采用浅色中性界面和单一绿色主强调色；涨跌、失败、警告可使用语义色。
- 控件圆角、间距、字体层级与状态反馈保持一致。
- 桌面端优先保证信息扫描效率，手机端显式重排，不对桌面布局做简单缩放。
- 所有关键页面需要覆盖加载、空数据、错误、中断和完成状态。
- 当前 `TA` 标识与绿色主题作为首版临时品牌；首版不建设深色主题。
- 正式实现前后均需在桌面与手机视口进行截图验收。

当前设计参数：

- DESIGN_VARIANCE：4，结构稳定，保留少量非对称层级。
- MOTION_INTENSITY：3，仅使用状态反馈和必要转场。
- VISUAL_DENSITY：7，适合日常高频使用的专业工作台。

## 6. 首版技术架构

已确认路线：

- FastAPI 提供应用 API。
- React、TypeScript、Vite 和 Ant Design 构建前端。
- SQLite 保存任务、配置、状态、摘要和完整报告。
- SSE 向浏览器推送阶段进度与新生成的报告内容。
- 任务执行器封装现有 `TradingAgentsGraph`。
- 首版同一时间运行一个分析任务，其余任务排队。
- 现有 Markdown 报告继续输出，作为兼容性与人工审计文件。

服务重启后的行为：

- 已完成任务保持可查看。
- 未完成任务标记为已中断。
- 如果存在有效 LangGraph 检查点，允许用户继续运行。
- 如果无法继续，允许用户使用原参数重新运行。

首版不提供主动取消正在运行的任务；关闭浏览器不会终止任务。PWA 安装与任务完成通知延后。

## 7. 首版明确不做

- 真实券商下单与账户连接。
- 多用户、团队、邀请、角色和权限管理。
- 评论、审批和共享链接。
- 自动交易策略调度。
- 实时持仓和盈亏管理。
- 面向公网匿名访问的安全模型。
- 原生 iOS 或 Android 应用。
- 复杂的密钥加密与外部密钥服务集成。
- 深色主题、PWA 安装和任务完成通知。
- 主动取消运行中的任务。

## 8. 后续再议

正式产品名称与长期品牌体系、深色主题、PWA、通知、自动清理期限和取消机制不阻塞首版，后续需求变更时再设计。当前均不得作为首版实现的既定能力。

## 9. 当前草图

草图页面：快速发起分析、任务运行、决策报告、任务历史和模型设置。

草图覆盖：

- 桌面端侧边导航、多栏布局、运行任务与最近决策。
- 手机端单列发起表单和底部导航。
- 股票或资产搜索下拉的展开状态。
- 运行阶段、当前 Agent 产出、实时动态与 Agent 状态。
- 最终评级、关键证据、主要风险和完整报告分区；草图中的“信号强度”仅是占位示例，正式实现不展示。
- 历史任务筛选、状态、报告入口与中断恢复入口。
- API Key、供应商连接测试、默认模型和检查点恢复设置。
- 示例数据仅用于说明信息层级，不代表真实行情或模型输出。
